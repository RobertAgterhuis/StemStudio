# Hand-off: qa / 002 us4 (T076)

## What was built

`e2e/tests/detail-split-further.spec.ts` (`@detail`):

- "a track without a detail phase can be split further and then offers expand": live phase on a
  per-run band copy, `POST .../detail/cancel` -> `cancelled`; on the track page the spec clicks
  `detail-split-further` or `detail-retry` (whichever is shown), waits for `completed`, checks the
  fake outcome table and that the mixer shows `expand-<parent>` for vocals, drums and other
  (US4 AS1, FR-009, quickstart D8).
- "a re-imported source completes its detail phase from the worker cache within 5 s": complete a
  phase, `DELETE` the track (204), upload the identical bytes again; `msFromStandardToDetail`
  (250 ms polling) measures standard-completed -> detail-completed and must be <= 5 s
  (US4 AS2, FR-010, SC-007, quickstart D9).

**Contract note (no change made):** spec US4 says cancelled tracks show "Split further", while
ui-test-ids 1.1.0 and frontend T074 show `detail-split-further` only for status `none` and
`detail-retry` for `cancelled`. A `none` track cannot be produced through E2E (every new import
auto-queues), so the spec accepts either button. The `none` case is covered by bUnit (T074) and
backend T072.

Coordinator notes from the merged frontend hand-off were checked: `expand-<parent>` is disabled
("Loading...") while a group loads; `MixerPage.setExpanded` already waits on
`aria-expanded="true"` (30 s) before touching strips. `track-action-error` and
`detail-outcome-bass` are not in ui-test-ids 1.1.0, so the specs do not use them.
