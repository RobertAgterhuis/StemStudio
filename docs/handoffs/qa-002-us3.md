# Hand-off: qa / 002 us3 (T071)

## What was built

- `e2e/tests/detail-progress.spec.ts` (`@detail`):
  - "an active detail phase blocks delete; after cancel the track can be deleted": per-run band
    copy with a live phase; `attemptDelete` (clicks `track-delete`, confirms if the UI asks) ->
    `track-delete-blocked` visible with a reason, `DELETE /api/tracks/{id}` = 409; `detail-cancel`
    -> `cancelled`, `detail-retry` shown, track still `completed` with 6 stems and no detail
    parents; delete then succeeds (FR-016, quickstart D11).
  - "a new import is separated while another track's detail phase is still running": track A
    `running`, upload B, B reaches `completed` while A is still `queued`/`running` (elapsed time
    annotated), then A completes (FR-011, SC-006, quickstart D7).
- `e2e/tests/detail-worker-restart.spec.ts` (`@detail @worker-restart`, opt-in): A `running` ->
  `docker compose -f $E2E_COMPOSE_FILE restart worker` (`support/stack.ts`, `execFileSync`
  argument list) -> `failed` with "interrupted by restart" and Retry, track `completed`, the
  mixer plays the standard stems, Retry -> `completed` with the fake outcome table (FR-019,
  US3 AS2/AS3, quickstart D6).
- `support/detail.ts`: `importWithLivePhase(api, salt, statuses)`, `attemptDelete`,
  `expectStillActive` (fails with a hint to start the stack with
  `STEMSTUDIO_FAKE_DETAIL_STEP_SECONDS=5` when a phase ended too early).

**Deviation:** TEST-STRATEGY (001) said the suite never restarts containers. The worker restart
must land inside a ~25 s window, which the 001 two-step `@restart` pattern cannot hit reliably, so
this one spec restarts the worker itself; it is opt-in (`@worker-restart`, excluded from
`npm test`) and documented in TEST-STRATEGY section 5.
