# Quickstart / validation: Library Care (feature 013)

Run from the repository root. PowerShell and bash variants are equivalent; bash is shown.
Validation ids V1-V10 are referenced by tasks.md (T068-T070).

## V1 Backups folder

```bash
mkdir -p backups                                   # default host folder (./backups next to the compose file)
# Linux hosts only: the API runs as uid 1654 in the aspnet image
sudo chown 1654:1654 backups
# Another location (e.g. an external drive):
export STEMSTUDIO_BACKUP_HOST_DIR=/mnt/usb/stemstudio-backups
scripts/check-backup-folder.sh                     # devops T011: exists, writable by uid 1654, free space
```

Windows (Docker Desktop): `$env:STEMSTUDIO_BACKUP_HOST_DIR = 'D:\StemStudio\backups'` before
`docker compose up`. Expected: Library care -> Backups shows the folder with its free space
(`backup-folder-state` `data-writable="true"`). Without the mount it shows `backup-folder-error`
with the fix, and Storage still works.

## V2 Fake stack

```bash
STEMSTUDIO_SEPARATOR=fake docker compose up -d --build --wait
```

Import three short fixtures (one URL, one upload, one with "Split further"), save a mix, export a
stem, make a score (fake transcriber). With the fake generative stack (009/010 quickstart) add one
generation and one voice profile.

## V3 Backup, lose everything, restore (SC-001)

```bash
# 1. In the UI: Library care -> Backups -> New backup -> Complete -> Start; wait for "Verified".
ls -l backups/                                      # stemstudio-backup-<timestamp>.zip, no .partial
unzip -l backups/stemstudio-backup-*.zip | tail -3  # manifest.json is the last entry
# 2. Lose all volumes
docker compose down -v
STEMSTUDIO_SEPARATOR=fake docker compose up -d --build --wait
# 3. In the UI: Library care -> Backups -> the archive -> Restore (empty library: no confirmation)
```

Expected: tracks, mixes, exports, scores, generations, lyrics sheets, styles and the voice profile
(with its consent details) are back; stems play; "Split further" on the detail track's other
parent works (the worker cache is rebuilt from the library: stage "Preparing stems").
`tests/fixtures/backup/compare_library.py <before.json> <after.json>` (qa) compares row dumps and
file hashes.

## V4 Write gate and cancel (FR-002, FR-006, SC-003)

During a backup of the V2 library: delete a track -> refused "A backup is running"; start an export
-> runs; cancel the backup -> within 5 s `cancelled`, no `.partial` left in `backups/`.

## V5 Replace, undo, discard (FR-012)

Make a backup, delete a mix and a track, restore with **Replace** (type `REPLACE`): the deleted
items are back and "Previous library" is shown. **Undo restore**: they are gone again (the previous
library is now the restored one). **Discard** (type `DISCARD`): the folder
`library-care/previous/` is empty (`docker compose exec api ls /data/library-care/previous`).

## V8 Storage and clean-up (US3, US4, SC-006, SC-007)

Library care -> Storage: compare with

```bash
docker compose exec api du -sb /data/tracks /data/assets /data/generations /data/voices
docker compose exec worker du -sb /data/cache /models/*
```

Then "Remove detail stems" (preview -> confirm): freed size equals the preview; the track shows

the worker cache still has the result). "Clear the worker cache", then "Split further" on another
track: rehydration, then the detail job runs.

## V9 Throughput on the reference machine (SC-002, CTO)

Record MB/s for backup, verify and restore in `docs/STATUS.md`; target >= 60 MB/s each. Repeat with

## V10 Restore while the API stops (SC-005)

Start a replace restore of a large archive; during "Switching" run `docker compose kill api`, then
`docker compose up -d api`. Expected: the library is either the previous or the restored one (the
journal recovery log line says which), `PRAGMA integrity_check` is `ok`
(`docker compose exec api sqlite3 /data/stemstudio.db "PRAGMA integrity_check"` when sqlite3 is
available, otherwise the API's health log), and the Backups tab shows the job as failed
"Interrupted by restart" or completed.
