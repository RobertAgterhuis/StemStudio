How it works

Three services on your own computer. The browser plays the stems itself, sample-locked through the Web Audio engine; the worker does the heavy lifting.

Tech stack

Web app
.NET 10, Blazor Web App (Interactive Server) with Radzen components, port 8080
API
ASP.NET Core Minimal API, EF Core with SQLite, local file storage, port 8081
Audio engine
TypeScript on Web Audio: sample-locked playback, mixer, post-fader peak meters, A-B loop, metronome on the audio clock (JS interop)
Worker
Python 3.12, FastAPI; yt-dlp, spotDL, ffmpeg, Demucs (htdemucs_6s, fallback htdemucs), librosa beat grid
Optional services
NVIDIA GPU image (CUDA); generator (ACE-Step 1.5) and singer (SoulX-Singer) for features 009 and 010; Ollama on the host for the composer agent (011)
Quality
At least 90 % line and branch coverage per component, SIG-style maintainability limits, Playwright end-to-end suite, SonarQube settings; see Development and quality gates

Personal practice and privacy

{{legal}}

This website sets no cookies and loads nothing from other servers: no analytics, no trackers, no external fonts. The theme you pick is kept in your browser's local storage and never leaves your device.

StemStudio itself is single-user and local. Online lookups for artwork and band info send only the song title, artist, duration and ISRC to the open data services, and you can switch them off.
